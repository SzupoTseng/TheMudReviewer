## 021　`dialects.js` — 方言 profile 表

**标签**：`#规格` `#方言` `#profile` `#撞号` `#查表`

### 导出

```javascript
export const KIND          // 17 种泛型结构
export const PROFILES      // { classic, dmjh, zymud }
export const PANEL_TITLE   // panel 名 → 中文标题
export function setDialect(name) → string
```

### `KIND`（**逐值照抄**）

```javascript
TEXT:'text'  LIST:'list'  ACTIONS:'actions'  BARS:'bars'
ENTITY_ADD:'entity.add'  ENTITY_DEL:'entity.del'
MESSAGE:'message'  TITLE:'title'  CLOSE:'close'
// 指游 ZY 的「客户端能力」类
CLEAR_MAIN:'clearMain'  RELOGIN:'relogin'  NETSTAT:'netstat'
HINT:'hint'  DAMAGE:'damage'  STORY:'story'  VIBRATE:'vibrate'  IGNORE:'ignore'
```

### profile 结构

```javascript
PROFILES = {
  classic: { label: '经典 zjmud',        ext: {} },
  dmjh:    { label: '大梦江湖（新协议）',  ext: DMJH },   // 73 笔
  zymud:   { label: '指游 MUD（ZY）',     ext: ZYMUD },  // 20 笔
}
```

每一笔的形状：

```javascript
'511': { name:'XYKILL', kind:KIND.ENTITY_ADD, panel:'combat', side:'enemy' }
'515': { name:'XYKILLMIAO', kind:KIND.MESSAGE, channel:'combat' }
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | ✅ | 原始宏名，调试用 |
| `kind` | ✅ | 决定用哪个解析器 |
| `panel` | `MESSAGE`/能力类以外必填 | 去哪个面板 |
| `slot` | 选填 | 面板内的字段；缺省为 `'body'` |
| `side` | `ENTITY_*` 必填 | `'ally'` / `'enemy'` |
| `channel` | `MESSAGE` 必填 | `'chat'` / `'combat'` / 其他→toast |

### `detectDialect(line)`（**方言判别**）

```
以 'version 1.0' 开头 → 'zymud'
以 'ver1.0'      开头 → 'dmjh'
其他                  → 维持现值
```

### `lookupExtended(op)`（**撞号处理**）

```
1. 目前 profile 的 ext 有 op → 回传
2. 否则扫所有 profile：
     恰好只有一个 profile 有 op → 回传（跨方言兼容）
     有两个以上（撞号）        → 回传 null（严格以目前 profile 为准）
```

> ⚠️ 第 2 步的「恰好一个」是关键。放宽成「取第一个」会让 602–605 的行为取决于对象键顺序。

### 已知撞号（**必须维持隔离**）

| opcode | dmjh | zymud |
|--------|------|-------|
| `602` | `DMZHUYET` | `ZYCHARHP` |
| `603` | `DMZHUYETY` | `ZYFIGHTBTN` |
| `604` | `DMZHUJMQH` | `ZYHANDLERBTN` |
| `605` | `DMZHUJIU` | `ZYCLEARSCREEN` |

`conflictingOpcodes()` 必须恰好回传这四个。**多出来代表新方言撞号了。**

### 扩充事件的产出（`decodeExtended`）

| kind | 事件 `type` | 额外字段 |
|------|------------|---------|
| `TITLE` | `panel.title` | `text` |
| `TEXT` | `panel.text` | `text` |
| `LIST` | `panel.list` | `items` |
| `ACTIONS` | `panel.actions` | `layout`, `items` |
| `BARS` | `panel.bars` | `layout`, `bars` |
| `ENTITY_ADD` | `panel.entityAdd` | `side`, `id`, `label`, `bar` |
| `ENTITY_DEL` | `panel.entityDel` | `side`, `id` |
| `CLOSE` | `panel.close` | — |
| `MESSAGE` | `msg.chat`/`msg.combat`/`msg.toast` | `text` |
| `CLEAR_MAIN` | `ui.clearMain` | — |
| `RELOGIN` | `conn.relogin` | `delayMs` |

## 022　`store.js` — 状态容器

**标签**：`#规格` `#状态` `#pubsub` `#通知传播`

### 导出

```javascript
export const DEFAULT_LIMITS = { main:500, chat:500, sys:500, combat:200 }
export function createStore(limits = DEFAULT_LIMITS) → StoreAPI
```

### `StoreAPI`

```javascript
{ get(path), set(path, value), patch(path, partial), sub(path, cb),
  pushMessage(channel, msg), clearMessages(channel),
  resetRoom(), reset(),
  extSet(panel, patch), extSlot(panel, slot, entry),
  extEntity(panel, side, entity), extEntityRemove(panel, side, id), extClose(panel),
  get state() }
```

### 初始状态（**完整结构**）

```javascript
{
  conn:  { state:'IDLE', host:null, port:null, retries:0, nextRetryMs:0,
           multiline:true, lastError:null },
  room:  { title:'', titleCmd:null, desc:'', descHidden:false,
           descForcedHidden:false, exits:[], titleButtons:[], objects:[] },
  stats: { bars:[], layout:null },
  msgs:  { main:[], chat:[], sys:[], combat:[] },
  target:{ id:null, name:null },
  overlay:{ kind:null, detail:'', promptTemplate:null, needNumber:false,
            actions1:null, actions2:null, dialog:null, map:'',
            paged:'', pagedPage:0, story:null, web:'', popMenu:null },
  quick: { slots:{}, showCustom:false },
  ext:   { panels:{}, active:null },
  ui:    { theme:'night', fontScale:1, combatVisible:false,
           chatTab:'chat', netStatVisible:false },
}
```

`conn.state` ∈ `IDLE | CONNECTING | OPEN | RECONNECTING | FAILED`

### `notify(path)` — 双向传播（**关键**）

```
① 往上：通知 path 与所有祖先 path 的订阅者
     'room.title' → 通知 'room.title'，再通知 'room'
② 往下：通知所有以 path + '.' 为前缀的订阅者
     'room' → 通知 'room.title'、'room.exits'、'room.objects'…
③ 最后通知 '*' 的订阅者
```

> ⚠️ **少了②会有实际 bug**：`resetRoom()` 只 `notify('room')`，订阅 `room.titleButtons` 的组件收不到通知，换房间后旧按钮残留在画面上。

### `set(path, value)`

值未变（`===`）时**不通知**。

### `pushMessage(channel, msg)`

推入后套用 `limits[channel]`，超过时从头 `splice` 移除最旧，然后 `notify('msgs.'+channel)`。

### `resetRoom()`（`ESC002` 的副作用）

清空 `room.exits`、`room.objects`、`room.titleButtons`、`room.titleCmd`、
`ui.combatVisible=false`、`msgs.combat` 清空、`quick.showCustom=false`，
然后 notify `room` / `ui.combatVisible` / `msgs.combat` / `quick`。

### `ext*` 系列

面板结构：

```javascript
panels[name] = { title:'', slots:{}, entities:{ ally:[], enemy:[] } }
```

- `extSlot(panel, slot, entry)`：`slot` 缺省为 `'body'`
- `extEntity(panel, side, entity)`：**依 `id` 去重**，已存在则覆写
- 任何 ext 写入时，若 `ext.active` 为空则设为该 panel
- `extClose(panel)`：删除该 panel；若它是 active，改指向剩下的第一个或 `null`
- 全部以 `notify('ext')` 通知

## 023　`main.js` — reducer 与登录状态机

**标签**：`#规格` `#reducer` `#登录` `#不变式`

### 数据流（**单向，不可逆**）

```
TCP 一行 → loginIntercept(raw) → decodeLine(raw) → applyEvent(ev) → store → UI
用户操作 → ctx.* → sendCommand → net.send
```

### **不变式（可测）**

> `decodeLine` 能产生的每一种事件 `type`，`applyEvent` 都必须有对应 `case`。

违反时的症状是「服务器叫客户端做某件事，客户端什么都没做，且不报错」。
附录 C 有一条测试用正则扫两个文件来守这条。

### `applyEvent` 对照表（**完整**）

| 事件 | 动作 |
|------|------|
| `conn.notice` | `reloginLook` 为真 → `sendCommand('l')`；再依 `text` 前 4 字符判断 `0007`（登录成功，关闭两个 modal、更新帐号标签）／`0008`（开建角 modal）／`0009`（建角错误） |
| `conn.multiline` | `store.set('conn.multiline', value)` |
| `conn.echo` | `sendCommand(cmd)` |
| `conn.relocate` | toast → `net.close()` → `net.connect(host, port)` |
| `conn.quit` | `confirm()` 后关闭窗口（**不可无条件 exit**） |
| `conn.relogin` | toast → `delayMs` 后 `net.close()` + 重置登录 + 开登录 modal |
| `room.title` | **先 `store.resetRoom()`**，再 `set('room.title')` |
| `room.desc` / `room.descToggle` | 设对应字段 |
| `room.exits` / `exitRemove` / `exitClear` | 设 / 过滤 / 清空 `room.exits` |
| `room.objects` / `objectRemove` / `objectBar` | 设 / 过滤 / map 上 `bar` |
| `stat.bars` | `set('stats', { bars, layout })` |
| `ui.titleButtons` | `set('room.titleButtons')` |
| `ui.quickButtons` | `bs` 槽 → `room.titleCmd`；其余写入 `quick.slots`；有非 bs 槽时 `quick.showCustom = true` |
| `msg.main/chat/toast/combat` | `pushMessage`；`toast` 另外显示横幅并写入 `sys`；`combat` 另外开战斗面板 |
| `msg.combatClose` | 关面板 + 清 `msgs.combat` |
| `msg.float` | 飘字动画 |
| `overlay.*` | `store.patch('overlay', {...})`，`kind` 决定显示哪一个 |
| `overlay.web` | **不内嵌**，改用外部浏览器打开（CSP） |
| `panel.*` | 调用对应 `store.ext*` |
| `ui.clearMain` | `clearMessages('main')` |
| `ui.vibrate` | `navigator.vibrate?.(durationMs)`，包 try/catch |
| `ui.netStat` | `set('ui.netStatVisible', enabled)` |
| `ui.hint` | 每笔 `text` 推入 `sys` 频道 |
| `ui.ignored` | 无动作（官方标为未实现） |

### `sendCommand(cmd)`（**唯一送出路径**）

```javascript
if (cmd == null || cmd === '') return;
const line = store.get('conn.multiline') ? cmd : cmd.split('\n').join(';');
net.send(line);
```

### 登录状态机

```javascript
login = { stage:'idle', id:'', password:'', email:'', manual:false,
          failures:0, dialect:'dmjh', charFields:3, loginFields:4 }
```

`loginIntercept(raw)` 在 `decodeLine` **之前**运行，处理三件事：

| 条件 | 动作 |
|------|------|
| `isChallenge(raw)` | 判别方言、设 `charFields`（zymud=2，否则 3）；有帐密→`doAutoLogin()`，否则开登录 modal |
| 含「账号在别处登录」 | `net.stopReconnect()` → **先开 modal 再写错误消息** |
| 含「花在连线进入手续的时间太久」 | `failures++`；≥3 → 停止重连 + 开 modal + 错误消息 |

> ⚠️ `openLoginModal()` 会清空错误列，所以**必须先开 modal，再调用 `showLoginError()`**。顺序反了消息会消失。

### `doAutoLogin()`（**两行连发**）

```javascript
net.send(LOGIN.ANY);                                   // 'x'
net.send(buildLoginLine({ ...login, fields: login.loginFields }));
```

两行必须在**同一个 tick** 送出。服务器对登录有逾时，中间不可有人工延迟。

### ★ 自动登录的帐密来源（**安全关键**）

```javascript
if (rmEl.checked) {          // 只有勾了「记住」才读
  login.id = prefs.accountId;
  login.password = prefs.accountPw;
} else {
  login.id = '';
  login.password = '';
}
```

> ⚠️ **绝不可从 DOM 输入框读值**。输入框带 `autocomplete="username"/"current-password"`，
> 浏览器密码管理员会自动填入——那是「帮用户少打字」，不是「用户同意自动登录」。
> 读 DOM 会让全新的浏览器设置档也跳过登录表单直接进游戏。

### `mount()`（**逐项隔离**）

```javascript
const mountErrors = [];
function step(name, fn) {
  try { fn(); } catch (err) { mountErrors.push(`${name}: ${err.message}`); }
}
```

挂载顺序（**关键项目必须各自独立保护**）：

```
Toast → FloatText → ConnBadge → RoomHeader → RoomDesc → EntityList
→ ExitPad → StatBars → QuickBar×2 → MessageList×4
→ InteractSheet → PopMenu → DialogModal → SimpleOverlay×2
→ CommandInput → ChatTabs → CombatPane → Settings → ConnectForm
→ LoginForms → ExtPanels
```

最后：还原偏好、套用主题与字级、若有 `mountErrors` 显示在连接面板。

另需安装全域 `error` 与 `unhandledrejection` 拦截，把未捕捉例外写进连接面板错误列。

> 💡 君之一席话
> **一份规格能不能被还原，看的不是它列了多少 API，而是它有没有把「这里顺序反了会怎样」写出来——正确的代码有很多种写法，错误的方式往往只有那几种。**

> 🔍 老手视角──真正的门道
> 本节那条「解码器产生的事件，reducer 必须全部处理」的不变式，是这份规格里最有价值的一行——因为它**可以被机器检查**。老手写规格时会刻意区分两种条款：**叙述性的**（「应该分层」）与**可验证的**（「用正则扫这两个文件，差集必须为空」）。前者靠自律，后者靠 CI。本项目的 ZY 方言就是在补完之后才发现有 7 种事件被解出来却没人处理——**如果那条不变式早一天存在，这个缺口根本活不到被发现**。可落地的做法：规格里每写一条「必须」，就问一句「这条能不能写成测试？」——不能的话，它多半只是愿望。
