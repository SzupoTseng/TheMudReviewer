# 第五篇　工程实务

## 015　七次事故 — 同一个症状，七种死法

**标签**：`#事故` `#调试` `#可观测性` `#测试盲区` `#复盘`
**证据等级**：🟢 全部为实机发生

**起源**：协议层测试全绿、Rust 编译零错误、实机封包逐行验证通过。交到用户手上，按下「连接」——**毫无反应**。

修好，再交，再无反应。**连续四次。**

第五次是能连上了，但流程走不完。
第六次是流程走得完了，但**用户打不完字**——输入完帐号，光标被弹回帐号栏，密码永远打不进去。

第七次最严重：它不是「不动」，是**动得太多**——客户端每秒对服务器登录一次，
等我们看服务器日志时，已经写进去 **50,251 次登录**。

七次的表面症状成因**完全不同**。

**技术内核**：

| # | 成因 | 为什么既有测试抓不到 | 修法 |
|---|------|---------------------|------|
| 1 | `Element.scrollTo()` 在某些环境不存在，于 `mount()` 期间抛错 → 后续 `bindConnectForm()` 从未运行 → 连接钮没有处理器 | 98 条测试全绕过 HTML + main.js 这一层 | 换 `scrollTop`；加失败隔离 |
| 2 | **Tauri v2 ACL**：缺 `capabilities/default.json`，`event.listen` 被权限系统拒绝 | 编译完全成功；权限是**运行期**才检查 | 添加 capabilities 白名单 |
| 3 | **npm 平台错配**：从 WSL 运行 `npm install`，装到 `@tauri-apps/cli-linux-x64-gnu`，Windows 版原生 binary 被覆盖 | 与代码无关，是环境问题 | 一律在 Windows 端跑 `npm install` |
| 4 | **`[hidden]` 被 CSS 盖掉** | jsdom 断言的是 `hidden` **属性**，不是实际可见性 | `[hidden] { display: none !important; }` |
| 5 | **没有登录接口**：要用户自己打三行，但服务器有逾时 | 设计时当成「已知限制」写进文档就放着了 | 客户端接手握手 |
| 7 | **重连风暴**：Rust 的 `connect()` 先关旧连接 → 旧连接 emit `closed` → 前端当成非预期断线而重连 → 又关旧的 → 循环。退避 1/2/4/8/16/30 秒**从未升级**，因为每次重连都成功、成功就把 `retries` 归零 | 假的 `__TAURI__` 对 `mud_connect` 直接「假装成功」，**从不仿真真 Rust 会关掉旧连接**——引发 bug 的那个动作在测试里不存在 | Rust 区分 `StopReason::{UserClose, Replaced}`；前端挡重入 |
| 6 | **登录窗口被反复重开，focus 一直跳回帐号栏**：服务器等待输入时会重送 `ver1.0:` 挑战行，每一行都调用 `openLoginModal()`，而它无条件 `focus('login-id')` | 测试只断言 `login-modal.hidden === false`，从不看 `document.activeElement`；而且测试只送**一行**挑战，真实服务器送很多行 | `openLoginModal()` 改成等幂：`if (!m.hidden) return;` |

**第 4 个影响范围最广，也最值得细讲。**

`[hidden]` 属性的 `display: none` 来自**浏览器 UA 样式表，优先级最低**。只要作者样式对同一个元素设了 `display`，`hidden` 就完全失效。

本项目有大量组件符合这个条件：

```css
.connect-panel  { display: grid; }   /* 连接面板 */
.modal-backdrop { display: grid; }   /* 对话框、弹出菜单 */
.overlay        { display: flex; }   /* 交互面板、地图、长文本 */
.entity-list    { display: flex; }   /* 对象清单 */
.exit-cell      { display: flex; }   /* 八方向键 */
```

于是 `panel.hidden = true` **毫无视觉效果**。连接其实**每次都成功**，只是面板不消失——用户看到的是「按了没反应」，实际上是每按一次就多连一条（那堆 `TIME_WAIT` 就是证据）。

**一行 CSS 修好全部**：

```css
[hidden] { display: none !important; }
```

**解决的痛点**：六次事故各自解决了一个层次的盲区——DOM 绑定、运行期权限、建置环境、视觉呈现、流程完整性、**重复事件对用户当下状态的破坏**。

**踩过的坑**：最大的坑不是这五个 bug，而是**我把「编译成功」当成「能用」，直接交出去**。前三次都是用户当测试员，一次修一个。

第四次才建了截屏工具，**第一次用就抓到面板根本没消失**。

**优点 / 罩门**：事后补上的两层测试（jsdom 冒烟 + 实机截屏）把这类问题挡在交付之前。罩门是它们比纯函数测试慢得多——jsdom 那 26 条要跑两秒多，实机截屏需要真的开窗口。**但相对于「用户连续四次替你调试」，这个成本便宜到荒谬。**

**盲区对照**：

| 测试层 | 抓得到 | 抓不到 |
|--------|--------|--------|
| 纯函数 | 协议解析错误 | 事件绑定、视觉、权限 |
| jsdom | 事件绑定、DOM 契约 | **CSS 级联、视觉可见性** |
| 实机截屏 | 视觉、版面 | 难以自动断言 |
| 真机连接 | 传输层、权限、环境 | 需要完整环境 |

**效益**：七个 bug，七种盲区，最终形成六层测试策略（见 016）。

**第 7 个最值得学的是诊断方法，不是修法。**
真因不是靠读代码猜的，是三个互相独立的量测把范围缩到一行：

| 量测 | 结果 | 排除了什么 |
|------|------|-----------|
| `grep -c` 服务器 log 的密码验证警告 | 50,251 次 | 确认规模，不是偶发 |
| 8 秒内 log 增加 4000 bytes | **稳定 1 Hz** | 排除退避重连（退避频率必定递减） |
| 关掉客户端 → log 增长归零 | 立刻停止 | 排除服务器自身、排除其他客户端 |

**「稳定 1 Hz」是破案的那一刀。** 它与任何指数退避都不兼容，
只可能来自「每次都成功、成功就把重试计数归零、然后又重来」。
看到固定频率的重复行为，不要往「重试逻辑写坏了」找，
要往「**成功路径把状态洗掉了**」找。

**第 7 个带来的纪律更根本：测试替身必须忠实仿真真实后端的副作用，包括不讨喜的那些。**
它不是「漏写一条测试」——覆盖率、测试数、全绿状态全都正常，
但假的后端从不做出「关掉旧连接并通知前端」这个真实会发生、而且会让调用端出错的动作。
**替身比真实宽容，是最难察觉的测试失效形态**，因为所有指针都告诉你一切正常。
判准只有一句：**这个替身有没有做出真实后端会做、而且可能让调用端出错的那些事？**

**第 6 个带来一条新的测试纪律**：
测试通常只喂**一次**事件，真实服务器会喂**很多次**。凡是由服务器推送而触发的 UI 动作，
测试就该送**至少两次**，并断言第二次没有破坏用户当下的状态——
focus 在哪、卷到哪、输入框里打了什么、哪个面板已展开。
这四样东西没有一样会出现在「功能有没有做出来」的断言里。

> 💡 君之一席话
> **同一个「它不动」，可以是绑定没跑、权限被挡、套件装错平台、CSS 盖掉属性、流程走不完、或是它动得太勤把你的光标抢走——症状相同不代表病因相近，这正是为什么「先让错误说话」比「猜哪里坏了」重要一百倍。**

> 🔍 老手视角──真正的门道
> 这六次事故有一条共同线索：**它们全都不会抛出用户看得到的错误**。编译成功、测试全绿、画面正常渲染——每一层都在说「没问题」，只有最后那个按钮沉默。老手面对这种「安静的失败」有一个标准动作：**先花二十分钟把错误变得可见，再开始找 bug**。本项目在连接面板加了错误列与环境诊断列之后，第 2 个 bug（Tauri ACL）是**它自己把答案印出来的**——`event.listen not allowed. Permissions: core:event:allow-listen`。在那之前，同样的问题只表现为「按了没反应」。可落地的提醒：**可观测性不是上线后的运维需求，是开发期的调试杠杆**；没有它，你的每一次修复都是在黑箱里掷骰子。

## 016　测试分层 — 为什么 98 条全绿还是不能用

**标签**：`#测试策略` `#分层` `#jsdom` `#视觉验证` `#回归`
**证据等级**：本项目 171 条测试

**起源**：项目初期只有三层测试：纯函数、状态容器、传输集成。98 条全绿。

**然后连续四次交付都是「按钮没反应」。**

原因很简单：那三层**全都绕过了 HTML + main.js + CSS**，也就是用户唯一会碰到的那一层。

**技术内核**：最终的六层策略：

| 层 | 文件 | 数量 | 涵盖 |
|----|------|------|------|
| 1 纯函数 | `protocol.test.mjs` | 57 | 样式方言、每个 opcode 的 payload、对话框、畸形输入 |
| 2 状态 | `store.test.mjs` | 8 | 订阅通知上下传播、容量裁切 |
| 3 对照真服务器 | `server-fixtures` / `live-capture` | 11+14 | 服务器宏展开的输出；**实机截取的原始封包** |
| 4 传输集成 | `integration` / `bridge` | 8+11 | 真开 TCP：假服务器 → 分行 → 解析 → store |
| 5 **UI 冒烟** | `ui-smoke.test.mjs` | **26** | **jsdom 真加载 index.html、真跑 main.js、真派发 click** |
| 6 方言兼容 | `dialects.test.mjs` | 33 | 三个 profile、撞号隔离、变长 opcode |

**第 5 层是分水岭。** 它是唯一会运行下列东西的测试：

- `index.html` 与 `main.js` 之间的 **DOM id 契约**
- `mount()` 是否真的跑完（字段有没有被填值，而不是只剩 placeholder）
- 按钮的**事件处理器有没有真的绑上**
- 服务器封包 → DOM 的完整渲染路径

用一个假的 `window.__TAURI__` 拦截 IPC，所以不需要 Tauri 就能在 CI 跑。

**第 3 层的实机封包**是另一个关键。53 行真实封包被固化成 fixture，例如：

```javascript
npc: `${E}005地藏王:look /d/register/npc/dizangwang#1686`,
```

这一条守住了「对象 id 含 `/` 与 `#`，只能切第一个冒号」这个规则——那是实机才会出现的形态，任何人造测试都想不到。

**解决的痛点**：把「我以为我测了」变成「我知道我测了哪一层、没测哪一层」。

**踩过的坑**：第 5 层仍然抓不到视觉问题。**jsdom 不做完整 CSS 级联**——`panel.hidden = true` 在 jsdom 里断言会通过，但真实浏览器中若作者样式设了 `display`，`[hidden]` 会被盖掉而画面完全没变。

这正是第 4 次事故的成因。所以又加了第七层：**实机截屏**。

```powershell
powershell -File tools\win\shot.ps1     # 截取窗口
powershell -File tools\win\drive.ps1    # 用剪贴板逐行送指令
```

改动 UI 之后**看一眼截屏**，成本几秒钟，能抓到所有纯 DOM 断言抓不到的问题。

**另一个坑是测试隔离**。UI 冒烟测试在同一个 jsdom 实例里跑，模块层级的 `login` 对象会跨测试残留。有一条「自动填入不该触发自动登录」的测试因此失败——不是代码错，是前一条测试留下的登录状态还在。

修法是在该测试开头先点「注销」清干净。**这个修法本身也揭露了一个真实时序**：`net.close()` 会解除事件监听，要等自动重连把监听绑回来，中间送的封包会没人收。

**优点 / 罩门**：分层的优点是**每一层跑的速度与涵盖面不同，可以分开调度**——纯函数在每次存盘跑，jsdom 在提交前跑，实机截屏在交付前跑。罩门是层数多了维护成本上升，且第 3 层的 fixture 会随服务器改版而过期。

**成本效益对照**：

| 层 | 运行时间 | 需要环境 | 抓到过几个真 bug |
|----|---------|---------|-----------------|
| 1 纯函数 | 180 ms | 无 | 多数协议解析错误 |
| 5 jsdom | ~2 s | jsdom | **2 个**（第 1、4 次事故） |
| 7 实机截屏 | ~15 s | 真窗口 | **1 个**（第 4 次事故的视觉确认） |

**效益**：测试代码占产品代码 40%（1,995 / 4,977 行）。这个比例不是刻意追求的，是被四次事故逼出来的。

> 💡 君之一席话
> **「测试全绿」只回答了一个问题：你测的那些是对的。它从不回答另一个问题——**你有没有测到用户会碰的那一层。

> 🔍 老手视角──真正的门道
> 测试分层真正的价值不在覆盖率数字，而在**每一层都明确声明自己抓不到什么**。本项目的每个测试档开头都写了这件事——`ui-smoke.test.mjs` 明确标注「jsdom 不做完整 CSS 级联，视觉问题请用截屏验证」。这行注解的价值超过十条测试，因为它让下一个人知道**该去哪里补**。老手审视测试策略时只问一个问题：**「从用户的手指到最底层的字节，这条路径上有哪一段没有任何测试经过？」**——把那段找出来，就是下一层测试该待的位置。可落地的做法：画一条从 UI 事件到 socket 的路径图，把每个测试档标在它覆盖的区段上，空白处一目了然。

## 017　环境陷阱 — 代码没错，错的是它跑的地方

**标签**：`#环境` `#WSL` `#跨平台` `#建置` `#编码`
**证据等级**：🟢 全部为实机踩到

**起源**：本项目原代码放在 Windows 磁盘，但开发指令常从 WSL 下达。这种混合环境有几个必踩的坑，而且它们的共同特征是——**代码完全正确，错的是环境**。

**技术内核**：

| 陷阱 | 症状 | 对策 |
|------|------|------|
| **npm 原生套件平台错配** | 从 WSL 跑 `npm install`，依 Linux 解析 optionalDependencies，装成 `*-linux-x64-gnu`，Windows 版消失，客户端起不来 | **`npm install` 一律在 Windows 端跑**。纯 JS 套件不受影响 |
| **WSL 连不到 Windows 的 127.0.0.1** | 明明服务器在跑，WSL 却 `ECONNREFUSED` | WSL2 有独立网络命名空间，要用缺省闸道 IP |
| **cmd 不吃 UTF-8 BOM** | `.bat` 第一行变成 `﻿@echo off` 而报错 | 存成**无 BOM** 的 UTF-8 |
| **REM 注解里的中文** | 冒出 `'x' is not recognized`，但功能其实正常 | cmd 在 `chcp 65001` 生效前预读后续字节。**注解一律用 ASCII**，中文只留在 `echo` 行 |
| **debug 版 exe 无法单独运行** | 双击得到 `ERR_CONNECTION_REFUSED` | `tauri dev` 另起静态服务器供应前端，debug binary 内嵌的是那个 URL。要独立运行档就 `tauri build` |
| **AV 误判新编译的 Rust exe** | 杀毒警告、可能隔离文件 | 无签章 + 全球唯一哈希 + 连外行为 → 启发式命中。把 `target` 与 `.cargo` 加入排除清单 |

**解决的痛点**：让「为什么在我机器上不能跑」有一份可查的清单，而不是每次重新推理。

**踩过的坑**：`npm` 平台错配这一条**造成了第 3 次事故**。当时为了装 jsdom 从 WSL 跑了 `npm install`，结果 Tauri 的 Windows 原生 binary 被 Linux 版覆盖，客户端直接起不来，错误消息是：

```
Cannot find native binding. npm has a bug related to optional dependencies
```

这个消息完全没提到「你在错的平台安装」，只说「找不到原生绑定」。**环境问题的错误消息通常最不友善**，因为工具作者没预期到你会这样用。

`REM` 中文那条也很典型：批量档**功能完全正常**，只是输出多了两行看不懂的错误。这种「坏得不明显」的问题最消耗信任——用户会开始怀疑其他一切。

**优点 / 罩门**：把环境陷阱写成清单的优点是**下次撞到能秒认**。罩门是清单会过期，而且它只涵盖你踩过的。

**跨环境成本对照**：

| 做法 | 开发便利 | 环境风险 |
|------|---------|---------|
| 全在 Windows | 低（缺 Unix 工具） | 最低 |
| 全在 WSL | 高 | 原生套件、GUI、网络都有坑 |
| **混合**（本项目） | 最高 | **中，需明确规则** |

本项目的规则很简单：**分析与测试在 WSL，安装与建置在 Windows。**

**效益**：六条规则，把一整类「不是代码的错」的问题变成可预防。

> 💡 君之一席话
> **最难除的 bug，往往不在你写的那几千行里，而在「你以为到处都一样」的那个假设里。**

> 🔍 老手视角──真正的门道
> 混合环境的问题有一个共同结构：**某个工具用「当前平台」做了隐含决策**。npm 用当前平台选 optionalDependencies、cmd 用当前 codepage 读文件、WSL 用自己的网络命名空间解析 localhost——每一个单独看都合理，组合起来就变成地雷。老手的应对不是记住所有陷阱，而是创建一条分界线：**「哪些指令必须在哪一侧跑」，写成规则贴在项目 README 的最上面**。本项目最后把这条写进了启动脚本的注解里，让下一个人在跑 `npm install` 之前就会看到警告。可落地的提醒：**任何跨环境项目，第一件事是画出那条线，而不是等它咬你。**
