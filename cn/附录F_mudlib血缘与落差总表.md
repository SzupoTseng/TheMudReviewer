## F.2　★ 握手的三个世代（本表最有价值的一栏）

把「握手」栏排一下，会看到一个**协议演化的横切面**——
这是 §044 逐行读 `logind.c` 时看不到的东西，**只有横向比对 17 份封存才会浮现**：

| 世代 | 握手行的形状 | 几份 | 意义 |
|------|------------|-----:|------|
| **① 明文** | **`ver1.0,123456789abcd`** | **4** | **`ZJKEY` 直接送上线路，完全没有哈希** |
| ② 旧 DES crypt | `ver1.0:byz0rmpISExtQ`（13 字符） | 1 | `crypt(ZJKEY, salt)` 的传统输出 |
| ③ SHA-512 crypt | `ver1.0,$6$<16字符salt>$<86字符>` | 10 | 现代 `crypt()` 的 `$6$` 格式 |
| ④ 无 | 不送版本挑战 / 纯 telnet | 3 | `damengjianghu`、`dongfanggushi2`、`nt7` |

**三个可以直接读出来的结论：**

1. **分隔符从 `:` 变成 `,`。** 世代 ② 用 `ver1.0:`，世代 ①③ 用 `ver1.0,`。
   本项目的客户端因此把握手行的比对写成 `/^ver1\.0[,:]/`——
   **那个字符集不是防御性写法，是量出来的**（§044、`telnetlogin.js`）。
2. **世代 ① 把密钥明文送出。** `123456789abcd` 就是 `zjmud.h` 里的 `ZJKEY` 常数。
   有 4 份 lib 的 `logind` 根本没调用 `crypt()`，直接 `write("ver1.0,"+ZJKEY)`。
   **而这完全不影响登录**——因为 §044 证明了 `jiance()` 根本不验证回应。
   **一个不验证的挑战，送明文或送哈希没有任何差别**，
   这也解释了为什么会有人把它简化掉。
3. **`crypt()` 的输出格式随系统而变。** 同一行 `crypt(ZJKEY,"byname666")`，
   在旧系统上得到 13 字符的 DES 输出，在现代 glibc 上得到 `$6$` 的 SHA-512 输出。
   **同一份原代码、不同的线路字节**——
   这正是本书「证据等级」要把实机封包排在原代码之前的理由（§01）。

> 💡 **这一节是本附录存在的理由**：单看一份封存，握手是一个固定格式；
> 横看 17 份，它是一条有世代、有分歧、有退化的演化线。
> **量测的价值往往不在单点，在横切面。**

## F.3　opcode 的实测分布

16 份会送 zjmud opcode 的 lib，在同一段流程（注册 → 建角 → 进世界 → look）中观察到的码：

| opcode | 几份送出 | 分布 | 语意（附录 A） |
|--------|--------:|------|--------------|
| `000` | **16/16** | ████████████████ | 登录／连接状态 |
| `002` | 14/16 | ██████████████ | 房间标题（**有清空副作用**） |
| `004` | 14/16 | ██████████████ | 房间描述 |
| `005` | 14/16 | ██████████████ | 房间对象 |
| `006` | 14/16 | ██████████████ | 自订按钮 |
| `003` | 13/16 | █████████████ | 出口（**§052：由 `set("exits/…")` 触发**） |
| `021` | 12/16 | ████████████ | 标题按钮 |
| `012` | 10/16 | ██████████ | 属性条群 |
| `022` | 7/16 | ███████ | 血条更新 |
| `014` | 5/16 | █████ | 代送指令 |
| `100` | 4/16 | ████ | 聊天 |
| `111` `234` `517` `604` `605` | 各 1/16 | █ | **全部来自 `damengjianghu` 一家**——方言扩充码 |

**三个结论：**

1. **交集只有 `000`。** 严格说来，「所有 lib 都会送」的只有登录状态一个码。
   这不代表其他码不通用，而是**触发条件不同**（有些 lib 进世界时不送属性条）。
2. **但 `002/003/004/005/006/021` 这六个在 12–14 份出现**——
   **这就是本书 §005 说的「最大公因数」在实测上的样子**：
   房间标题、出口、描述、对象、按钮、标题列，
   撑起主画面的那一组码，跨方言高度一致。
3. **长尾全部集中在单一 lib。** 5 个只出现一次的码全来自 `damengjianghu`（新协议版）——
   §009「定义 ≠ 使用」与 §010「撞号」的现象，在这张表上是可见的：
   **扩充码几乎不跨 lib 流通。**

> ⚠️ **这张表的已知偏差**（诚实揭露）：
> ① 只涵盖一段很短的流程，战斗、交易、对话类的码不会出现；
> ② §052 发现有些码由**数据写入**触发（`set("exits/…")` → `ESC003`），
> 这类码的出现与否取决于该 lib 的起始房间有没有动到那些属性——
> **所以 `003` 的 13/16 不代表有 3 份不支持出口，只代表那次没触发。**

## F.4　WASM 落差：所有 lib 的共同缺口

| 缺口 | 影响几份 | 缺的 efun | 后果 |
|------|--------:|-----------|------|
| **`package sockets` 关闭** | **14 份**（各 1–3 个对象加载失败） | `socket_create`、`socket_bind`、`socket_close`、`socket_write` | **§049 那整套 intermud 不存在**（跨服聊天、mudlist、gtell） |
| **ICU 无表格式字集** | 全部 | — | 导入时必须把整份 lib 转成 UTF-8（见 F.5） |
| 无 eval limit | 全部 | — | LPC 无穷循环会卡死分页 |
| MEMFS 不落地 | 全部 | — | 重整即失 |

**加载失败最多的是 `lpmudname`（3 个）**：
`/adm/daemons/kuafu`（跨服）、`/adm/daemons/qqd`、`/adm/daemons/miraid`。

> **driver 照常完成开机。** preload 清单里的项目加载失败只会让那个对象不存在，
> 不会中止启动（§038、§041）——这正是 `playable` 与 `noboot` 的分界：
> **看的是「进不进得了世界」，不是「有没有错误消息」。**
>
> 这些 daemon **不打算修**：它们只在有对外网络时才有意义，
> 而 WASM 版整个没有网络——**修了也没有对象可连**（§049）。

## F.5　导入时做了什么（可重跑）

| 处理 | 规模 | 为什么 |
|------|------|--------|
| **GBK → UTF-8 转档** | **最多单一 lib 29,853 档**（`xiaoaojianghu`）；14 份 lib 合计逾 **17 万档** | WASM 版 ICU 只带算法式字集，GBK 会 raise error（§041） |
| `set_encoding("非UTF")` 改写 | 逐 lib 1–2 处 | 同上 |
| **移除玩家存盘** | **`nt7` 一份就 630 个含密码栏的 `.o`** | 原营运者的真实玩家数据，对展示站无用途，**留着只是外泄风险** |
| 凭证扫描 | 全部 | 见仓库 `SECURITY_NOTES.md` |
| 略过文件 | 运行档、备份、日志、`OBJ_DUMP` | 映像体积与安全 |

**全部由 `webclient/tools/import-lib.mjs` 产生，改动皆可重跑复现**——
每一份 `libs/<slug>/NOTES.md` 就是该次导入的完整纪录。

## F.6　怎么重跑这些量测

```bash
# ① 血缘（§050 的 Jaccard 矩阵）——只读索引，不必解开映像
python3 - <<'EOF'
import json, glob, itertools
S = {p.split('/')[1]: {f['path'] for f in json.load(open(p, encoding='utf-8'))['files']}
     for p in sorted(glob.glob('libs/*/mudlib.json'))}
for a, b in itertools.combinations(S, 2):
    j = len(S[a] & S[b]) / len(S[a] | S[b])
    if j >= 0.30: print(f'{j:.2f}  {a} ↔ {b}')
EOF

# ② 开机测试（分级、opcode、握手、加载失败）
node webclient/tools/boot-test.mjs            # 会把结果写回各 lib 的 NOTES.md

# ③ 全链路（真 DOM + 真 wasm driver + 真 HTTP）
node webclient/tools/verify-fullstack.mjs

# ④ 看某个 lib 的原始 LPC
node webclient/tools/unpack-lib.mjs libs/<slug> --out /tmp/<slug>
```
