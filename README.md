## 證據等級

書裡每一條協議斷言都標了它的出處。**衝突時的順序永遠是：**

```
🟢 實機封包  >  🟡 伺服器原始碼  >  🟠 客戶端反編譯  >  🔴 推論
```

這條規矩救過命：有兩處照客戶端反編譯寫得很篤定，被伺服器原始碼直接推翻；還有一處三方都同意，卻在真機上發現多了六組 telnet 協商位元組——那六組差點讓連線在第一個位元組就死掉。

## 立場說明

- 全書使用**中性的資深工程師**視角，不綁定任何公司或職級。
- **不美化過程**。七次事故全部寫進書裡，包括「把編譯成功當成能用、直接丟給使用者當測試員」的判斷失誤。
- 客戶端為**淨室實作**：僅依據對外部行為的觀察整理出互通性規格，未複製原始碼或資源。協議格式本身是互通所必需的事實資訊。
- 原 MUD 伺服器原始碼的授權條款請見各自倉庫，其中明載「**開源代碼嚴禁出售**」。
