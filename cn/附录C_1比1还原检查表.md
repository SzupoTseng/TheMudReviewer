### C.3.1　★ 四条「不可省」的不变式测试

还原时最容易漏掉、但漏掉就会静默坏掉的四条：

**① 事件与 reducer 必须全覆盖**

```javascript
const produced = new Set([...protoSrc.matchAll(/type: '([a-zA-Z.]+)'/g)].map(m => m[1])
  .filter(t => t.includes('.') && !t.endsWith('.')));
const handled  = new Set([...mainSrc.matchAll(/case '([a-zA-Z.]+)':/g)].map(m => m[1]));
assert.deepEqual([...produced].filter(t => !handled.has(t)).sort(), []);
```

> 这条测试在本项目上线前抓到 **8 个真实缺口**（`conn.relogin`、`overlay.story`、
> `overlay.storyClose`、`ui.clearMain`、`ui.hint`、`ui.ignored`、`ui.netStat`、`ui.vibrate`）——
> 全都解析成功、全都掉进 `default: console.warn`，画面上什么也不会发生。

**② 撞号必须恰好是那四个**

```javascript
assert.deepEqual(conflictingOpcodes(), ['602', '603', '604', '605']);
```

多出来代表新加的方言表撞到别人；少了代表 profile 被合并了。

**③ 测试替身不可比真实后端宽容**

```javascript
// 假 Tauri 的 mud_connect 必须仿真「先关掉旧连接」这个真实副作用，
// 否则重连风暴类的 bug 在测试里永远不会出现（2026-07-29 事故，五万次登录）。
```

**④ 自动填入的帐密不可被当成同意**

```javascript
// 在登录框塞值但 rememberAccount 为 false → 送出的封包不得含该帐号
```

## C.6　还原时最容易掉进去的八个坑

| 坑 | 症状 | 规格出处 |
|----|------|---------|
| 缺 `[hidden] { … !important }` | 面板永远关不掉，像是「按钮没反应」 | §026.3 |
| 用了 `Element.scrollTo()` | jsdom 下 mount 中断，连接钮未绑定 | §024.3 |
| 缺 `capabilities/default.json` | Tauri 版 `event.listen not allowed` | §028.3 |
| 缺 `withGlobalTauri: true` | 桌面版误判成浏览器环境，完全连不上 | §028.4 |
| 用 `read_line` 读 socket | telnet IAC 字节混进文本，首行就乱 | §028.5 |
| 三方言合并成单一 opcode 表 | 602–605 静默覆盖，某个 mudlib 的四个功能失效 | §021 |
| `connect()` 不挡重入 | **每秒重连一次、对服务器狂送帐密**（实际发生：50,251 次登录） | §027 |
| Rust 为「被取代的连接」emit closed | 同上，这是风暴的源头 | §028.2 |

> 💡 君之一席话
> **一份规格够不够格叫规格，看的不是它写了多少，而是照着它做出来的东西，能不能用同一份测试证明自己是对的。**

> 🔍 老手视角──真正的门道
> 这份检查表真正的设计重点在 C.3.1 那三条不变式测试——它们不验证「功能对不对」，而验证「**结构有没有裂开**」。一般测试检查已知输入产生已知输出；不变式测试检查的是「所有被产生的事件都有人处理」「撞号集合恰好是这四个」这种**跨文件的全称命题**，它们在你添加一个 opcode 却忘了写 reducer 时当场失败，而普通测试永远不会——因为没人会替一个自己忘了存在的功能写测试。可落地的做法：任何「A 文件产生的东西必须被 B 文件消费」的关系，都值得写一条用正则表达式扫原代码的不变式测试。它很粗糙、会有伪阳性，但它抓的是**遗漏**，而遗漏是唯一无法靠写更多测试补上的缺陷类型。
