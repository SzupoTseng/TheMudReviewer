### 018.2　依赖律（**强制**）

```
        main.js
       ╱   │   ╲
   net.js  │   ui.js
      │    │    │
      │  store.js
      │    ▲    │
      └────┴────┘
           │
      protocol.js ──▶ ansi.js ──▶ dialects.js
```

**四条不可违反的规则**：

1. `ansi.js`、`protocol.js`、`dialects.js`、`store.js` **不得引用 `document` / `window` / `localStorage`**
2. `ui.js` 只读 `store`、只调用 `ctx.*`，**不得引用 `net.js` 或 `protocol.js`**
3. 没有任何模块反向依赖 `main.js`
4. `protocol.js` 的输出是**数据**，不是副作用

**验收方式**：在 `node --test`（无 DOM 环境）中直接 `import` 前四个模块，不得抛错。

## 019　`ansi.js` — 样式方言解析

**标签**：`#规格` `#ansi` `#纯函数` `#状态机`

### 导出

```javascript
export const ESC = '';

export function parseStyled(raw, options?) → { spans, clearScreen }
export function stripStyles(raw) → string
export function classifyLink(url) → { kind, value }
```

### `parseStyled(raw, options)`

| 参数 | 类型 | 说明 |
|------|------|------|
| `raw` | `string` | 含 `ESC` 的文本。非字符串或空字符串回传空结果 |
| `options.state` | `object?` | 跨调用延续的样式状态；不给则每次从干净状态开始 |
| `options.dayMode` | `boolean?` | 白天模式色彩改写 |

**回传**：

```javascript
{
  spans: [{ text: string, style: Style }],
  clearScreen: boolean     // 遇到 [2J 时为 true
}
```

**Style 对象**（每个字段缺省 `null` / `false`）：

```javascript
{ fg, bg, bold, size, link, fullwidth }
```

### 算法（**逐步照做**）

```
1. 若 raw 以 ESC + "[2;37;0m" 开头（9 字符）→ 重置 style，raw 切掉前 9 字符
2. 以 ESC 切段
3. 第 0 段是纯文本（在任何 ESC 之前）
4. 其余每段调用 applySegment(seg, style)，就地更新 style，回传剩余文本
5. 若 style.fullwidth，文本先过 toFullWidth()
6. 每段产生一个 { text, style: {...style} }（**必须浅拷贝**，否则所有 span 共用同一个对象）
```

### `applySegment` 的判断顺序（**顺序不可改**）

```
① seg 以 "[u" 开头 → 找 "]"，取 slice(2, end)，剥除开头冒号 → style.link
② seg 以 "[s" 开头 → 同上，parseInt → style.size = +(30 / n).toFixed(3)
③ seg 以 "[2J" 开头 → clearScreen = true，切掉 3 字符
④ seg 以 "[H"  开头 → 切掉 2 字符（无视觉效果）
⑤ 其余：找第一个 "m"
     - 找不到或不以 "[" 开头 → 整段是文本
     - code === "[0m" 或以 ";0m" 结尾 → 重置全部
     - "[1m" → bold
     - "[9m" → fullwidth
     - 以 "[f#" 开头 → fg = normalizeColor(...)
     - 以 "[b#" 开头 → bg = normalizeColor(...)
     - 正则 /^\[(1;)?(\d{2})(;1)?m$/ → 查调色板
     - 都不match → 忽略指令、保留文本（降级，不丢弃）
```

> ⚠️ **①②必须在⑤之前**。`[u:` 与 `[s:` 以 `]` 收尾，用「找第一个 m」会解错。

### 调色板（**逐值照抄**）

```javascript
FG    = ['#000000','#aa3300','#00bb00','#eeee00','#0000aa','#aa00aa','#00bbbb','#aaaaaa']
FG_HI = ['#000000','#ff3300','#88ff00','#ffff00','#0000ff','#ff00ff','#88ffff','#ffffff']
BG    = ['#222222','#aa0000','#00aa00','#aaaa00','#0000ff','#aa00aa','#00aaaa','#aaaaaa']
BG_HI = ['#000000','#ff0000','#00ff00','#ffff00','#0000ff','#ff00ff','#00ffff','#ffffff']
```

**白天模式改写**：索引 `{2,3,6,7}`（即 32/33/36/37）一律改成索引 4（蓝）。

### `normalizeColor(hex)`

| 输入 | 输出 | 说明 |
|------|------|------|
| `#RRGGBB` | 原样 | |
| `#AARRGGBB`（8 位） | `#RRGGBBAA` | **ARGB → RGBA，alpha 从头搬到尾** |
| `#RGB` | 原样 | |
| 其他 | `null` | 调用端保留原值 |

### `toFullWidth(s)`

`0x20` → `U+3000`；`0x21`–`0x7E` → 加 `0xFEE0`；其余不变。

### `classifyLink(url)`

| 前缀 | kind | value |
|------|------|-------|
| `cmds:` | `'cmd'` | 去前缀 |
| `pops:` | `'pop'` | 去前缀 |
| `voice:` | `'voice'` | 去前缀 |
| 其他 | `'external'` | 原样 |

> `tel:` 与 `mailto:` 归入 `external`，由调用端交给系统处理。

## 020　`protocol.js` — opcode 解析

**标签**：`#规格` `#opcode` `#事件` `#纯函数`

### 导出

```javascript
export const SEP    // 分隔符常数
export const LOGIN  // 登录握手常数

export function parseLine(raw)                → { op, payload, resetStyles }
export function takeLayout(payload, defaults) → { layout, rest }
export function decodeLine(raw)               → Event
export function parseDialog(payload)          → Dialog
export function expandInputTemplate(tpl, v)   → string
export function expandDialogCommands(cmds, n) → string[]
export function isChallenge(line)             → boolean
export function buildLoginLine({...})         → string
export function buildCharLine({...})          → string
export function applyDialectFromChallenge(l)  → string
```

### `SEP` 常数（**逐值照抄**）

```javascript
{ REC:'$zj#', REC2:'$z2#', BR:'$br#', DIALOG:'$dh#', CMDSEQ:'$sock#',
  FIELD:':', SUB:'|', BAR:'║', NUM:'$N', KEEP:'$txt#' }
```

### `LOGIN` 常数

```javascript
{ CHALLENGES: ['ver1.0:', 'ver1.0,', 'version 1.0'],
  VERIFIED: '版本验证成功',
  OK: '0007', NEED_CHAR: '0008', BAD_NAME: '0009',
  SEP: '║', ANY: 'x' }
```

### `parseLine(raw)` — 变长 opcode（**关键**）

```
1. 非字符串 → { op: null, payload: '' }
2. 若以 ESC+"[2;37;0m" 开头 → resetStyles = true，切掉 9 字符
3. 长度 < 4 或首字符非 ESC → { op: null, payload: line }
4. three = line.slice(1,4)
   若 three 不match /^[0-9a-z]{3}$/i → { op: null, payload: line }
5. four = line.slice(1,5)
   若 four match /^[0-9a-z]{4}$/i 且 isKnownOpcode(four) 且 !isKnownOpcode(three)
       → { op: four, payload: line.slice(5) }
6. 否则 → { op: three, payload: line.slice(4) }
```

`isKnownOpcode(op)` = 在内核表 **或** 任一 profile 的扩充表中。

> ⚠️ 第 5 步的**两个条件缺一不可**。少了 `!isKnownOpcode(three)`，`ESC004` + 内容「5 个人…」会被误读成 `ESC0045`。

### `takeLayout(payload, defaults)`

payload 以 `$` 开头时，取到第一个 `#` 之间的字符串，以 `,` 切成 4 个整数；非数字者用 `defaults` 对应位补。回传 `{ layout: number[4], rest }`。

**各 opcode 的默认值**：

| opcode | defaults | 语意 |
|--------|----------|------|
| `008`/`009` | `[1,3,9,30]` | cols, widthDiv, heightDiv, fontDiv |
| `012` | `[0,0,22,35]` | cols(0=自动), 未用, heightDiv, fontDiv |
| `020` | `[1,2,8,25]` | cols, widthDiv, heightDiv, fontDiv |

`012` 的 `cols` 为 0 时，取 `ceil(bars.length / 2)`。

### 各 payload 的解析规则

**`003` 出口**：`dir:label[:cmd]` × `$zj#`。第 3 栏省略时 `cmd = dir`。
`slot` 由 `DIR_SLOT` 表查得，未列出者为 `null`（额外出口）。

```javascript
DIR_SLOT = {
  north:'n', northup:'n', northdown:'n',
  south:'s', southup:'s', southdown:'s',
  east:'e',  eastup:'e',  eastdown:'e',
  west:'w',  westup:'w',  westdown:'w',
  northwest:'nw', northeast:'ne', southwest:'sw', southeast:'se',
}
```

**`005` 对象**：`label:cmd` × `$zj#`，**只切第一个冒号**（指令含 `/` 与 `#`）。payload 长度 ≤ 4 视为空清单。

**`006` 按钮**：先把 `$br#` 换成 `\n`，再 `slot:label:cmd` × `$zj#`。slot ∈ `bs`, `b1`–`b17`。

**`008`/`009` 动作**：`主标题[|副标题]:指令` × `$zj#`。
- 指令含 `ESC020` → `popup` = 其后内容
- 指令含 `$txt#` → `keepOpen: true`

**`012` 属性条**：`║` 分隔；每笔 `标签:数值:颜色[:指令]`。数值三种形态：

| 形态 | mode | 说明 |
|------|------|------|
| `a/b/max` 且 max>0 | `'dual'` | 双层条 |
| `a/max` 且 max>0 | `'single'` | 单层条，b=max |
| 其他 | `'text'` | 不画条，`text` = 原字符串 |

**`020` 弹出菜单**：`label|cmd` × **`$z2#`**（不是 `$zj#`）。

**`022` 血条**：`tag$zj#a:b:max`。

**`010` 对话框**（`parseDialog`）：payload 以 `$dh#` 切块，逐块看前 5 字符：

| 前缀 | 动作 |
|------|------|
| `ok11.` | 推入 `okCmds` |
| `no11.` | 设 `cancelCmd` |
| `numb.` | `needNumber = true`（**长度等于 5 也要接受**） |
| 其他 | 内容块，以 `$br#` 切行 |

内容行：

| 前缀 | block |
|------|-------|
| `$exp#` | `{ kind:'exp', text }` |
| `$god#` | `{ kind:'money', text }` |
| `$obj#` | `{ kind:'item', tag, image, tier }`（`tag,image,品阶` 以 `,` 切） |
| `#RRGGBB` | `{ kind:'text', color, text }` |
| 其他 | `{ kind:'text', color:null, text }` |

品阶对照：`1`白 `2`绿 `3`蓝 `4`紫 `5`金 `6`红 `7`灰，其他 `default`。

### 两个占位符（**不可混用**）

```javascript
expandInputTemplate(tpl, v)   // ESC001：含 $txt# 则替换，否则 tpl + ' ' + v
expandDialogCommands(cmds, n) // ESC010：$N 替换成 n，再以 $sock# 拆成多条
```

### 登录辅助

```javascript
isChallenge(line)   // 前缀命中 LOGIN.CHALLENGES 任一
buildLoginLine({ id, password, email, secret='byname666', fields=4 })
  // fields===3 → id║pw║secret
  // 否则        → id║pw║secret║email
buildCharLine({ sex='男', avatar='', name, fields=3 })
  // fields===2 → sex║name
  // 否则        → sex║avatar║name
```

> 💡 君之一席话
> **一份能被 1:1 还原的规格，不是把代码翻译成中文，而是把「为什么是这个顺序」也写进去——顺序才是真正的规格。**

> 🔍 老手视角──真正的门道
> 写可还原规格时，最常被漏掉的是**判断顺序**与**默认值**。本篇 `applySegment` 那五步的顺序、`takeLayout` 各 opcode 的不同 defaults，都是实作者最容易自己「合理化」成别的样子的地方——而一旦顺序错了，测试会通过大半、只在特定输入上崩。老手交付规格时会刻意在每个顺序敏感处加上「⚠️ 顺序不可改」与**一个会失败的反例**，因为反例比正例更能锁死行为。可落地的做法：规格里每一条「必须先做 X 再做 Y」，都要附一句「否则 Z 会被误判成 W」。
