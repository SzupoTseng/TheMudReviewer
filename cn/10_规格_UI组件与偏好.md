## 024　`ui.js` — 15 个组件工厂

**标签**：`#规格` `#UI` `#无框架` `#差异更新`

### 024.1　共同形状

**每个组件都是一个工厂函数**，签名一律是：

```javascript
export function ComponentName(root, { store, ctx, ...opts })
```

- `root` — 已存在于 `index.html` 的挂载节点
- `store` — 状态容器（组件**只读**）
- `ctx` — 回呼包（组件**只调用**，不自己送封包）
- 回传值多半是 `undefined`；`MessageList` 回传 `{ destroy }`

**三条铁律**（违反其一，这一层就不再可测、不再可换）：

1. 组件**不解析协议**。它拿到的 `store` 里已经是解析好的结构。
2. 组件**不直接调用 `net.send`**，一律走 `ctx.send(cmd)`。
3. 组件在建构时订阅 `store.sub(path, render)`，之后只做**差异更新**，不整棵重建。

### 024.2　`ctx` 回呼契约（**15 个键**）

`main.js` 创建一个 `ctx` 对象传给所有组件。少一个，对应的交互就静默失效：

| 回呼 | 何时被调用 |
|------|-----------|
| `send(cmd)` | 任何按钮／链接要送指令 |
| `onLink(link)` | 点到样式方言的 `[u:…]` 链接 |
| `selectTarget(obj)` | 点现场对象 |
| `requestMap()` | 点方向盘中心 |
| `runAction(item)` | 点交互表单的动作 |
| `submitPrompt(text)` | 交互表单的文本输入送出 |
| `confirmDialog(num)` / `cancelDialog()` | 对话框确定／取消 |
| `closeOverlay()` | 关闭任何叠层 |
| `editQuickSlot(slot)` | 长按或右键快捷键 |
| `setExtPanel(name)` / `closeExtPanel()` | 扩充面板切页／关闭 |
| `retryNow()` | 连接徽章的「重新连接」 |
| `savePref(partial)` | 组件层改动需要持久化的偏好 |
| `dayMode` | **不是函数**，是布尔值，供 `parseStyled` 决定日间配色 |

### 024.3　DOM 小工具（3 个）

```javascript
el(tag, attrs = {}, children = []) → HTMLElement
```

`attrs` 的特殊键：`class` → `className`；`text` → `textContent`；`html` → `innerHTML`；
`on*` 且值为函数 → `addEventListener(小写事件名)`；`style` 且为对象 → `Object.assign`。
其余走 `setAttribute`，值为 `true` 时设成空字符串。**值为 `null`／`false` 的键直接跳过。**

```javascript
clear(node)             // while (firstChild) removeChild
scrollToBottom(node)    // ★ node.scrollTop = node.scrollHeight，包在 try/catch
```

> **★ `scrollToBottom` 不可改用 `Element.scrollTo()`。**
> jsdom 与部分 WebView 没有这个方法，会抛 `TypeError`；而它是在 `mount()` 期间被调用的，
> 一抛就中断整个挂载流程，后面的 `bindConnectForm()` 从未运行——
> 症状是「画面看起来正常，但『连接』钮完全没有反应」。这是本项目第一次事故的成因。

### 024.4　`renderStyled(raw, ctx)` — 纯数据与 DOM 之间唯一的桥

```javascript
→ { frag: DocumentFragment, clearScreen: boolean }
```

算法：

1. `parseStyled(raw, { dayMode: ctx?.dayMode })` 取得 `spans`
2. 每个 span 建一个节点：有 `style.link` 用 `<a class="lnk">`，否则用 `<span>`
3. **文本一律走 `textContent`**（★ 绝不 `innerHTML`——指游方言可带任意标签）
4. 样式逐项套：`color` / `backgroundColor` / `fontWeight:'700'` / `fontSize: ${size}em`
5. 链接节点另设 `dataset.linkKind`、`dataset.linkValue`、`href='#'`，
   `click` 时 `preventDefault()` 后调用 `ctx.onLink(link)`

### 024.6　`MessageList` 的差异更新算法（**最容易写错的一段**）

```javascript
let rendered = 0;
function render(list) {
  if (rendered > list.length) { clear(root); rendered = 0; }      // ① store 裁切或清空过
  while (root.childElementCount > list.length) root.removeChild(root.firstElementChild);
  for (let i = rendered; i < list.length; i++) {                  // ② 只画添加的
    const line = el('div', { class: 'msg' });
    const { frag, clearScreen } = renderStyled(list[i], ctx);
    if (clearScreen) { clear(root); rendered = 0; }               // ③ ESC[2J
    line.append(frag);
    root.append(line);
  }
  rendered = list.length;
  if (limit && root.childElementCount > limit) { … }              // ④ DOM 上限
  scrollToBottom(root.parentElement);                             // ⑤ 卷的是外层 scroll-pane
}
```

四个必须同时成立的条件：**只 append 新的**（500 则时整串重绘会明显卡顿）、
**裁切时同步移除旧节点**、**`ESC[2J` 要能清空**、**卷动对象是 `root.parentElement`**。

## 025　`prefs.js` — 本地偏好

**标签**：`#规格` `#持久化` `#安全`

### 导出

```javascript
export function loadPrefs() → Prefs        // 有内存缓存
export function savePrefs(partial) → Prefs // 浅层合并后写回
export function pushHistory(cmd) → string[]
```

### 保存键与默认值（**完整**）

```javascript
const KEY = 'zjmud.prefs.v1';

const DEFAULTS = {
  theme: 'night',            // night | day | mud
  fontScale: 1,
  descHidden: false,
  lastHost: '127.0.0.1',
  lastPort: 5001,            // ★ UTF-8 端口。5003 是 GBK，连了会乱码
  autoConnect: true,
  rememberAccount: false,    // ★ 缺省 false —— 帐密是 opt-in 才记
  accountId: '',
  accountPw: '',
  accountEmail: '',
  quickSlots: {},            // slot → { label, cmd }
  history: [],
  historyLimit: 200,
};
```

`loadPrefs()` 读不到或 JSON 坏掉时，**静默回退到 `DEFAULTS`**，不可抛例外——
它在 `mount()` 最前面被调用，一抛就整个画面起不来。

`pushHistory(cmd)`：空字符串不记；**与上一笔相同不重复记**；超过 `historyLimit` 从头截断。

### ★ 帐密的保存立场

密码以明文存在 `localStorage`。这是刻意的取舍，理由必须写进交接文档：

- ZJMUD 协议本身就是**明文传输**，本地加密不会提高真实安全性，只会制造安全感
- 但仍设成 **opt-in**：`rememberAccount` 缺省 `false`，用户不勾就完全不写

**与此配套的一条规则在 §023**：自动登录的帐密**只能来自 `prefs`**，
永远不可从 DOM 输入框读取——否则浏览器的密码管理员自动填入的内容，
会在用户毫不知情的情况下被送到服务器。这是本项目第五次事故。

> 💡 君之一席话
> **UI 层最好的规格不是「画面长什么样」，而是「它被允许调用谁」——把 15 个回呼列清楚，这一层就再也不会偷偷去解协议。**

> 🔍 老手视角──真正的门道
> 这一章值得注意的是 024.2 那张 `ctx` 表：它其实是一份**能力清单**（capability list）。无框架的 DOM 代码最常见的腐化路径，是某个按钮「顺手」直接 import 了 `net.js` 去送封包，于是 UI 层开始知道协议、测试开始需要真实连接、换后端时漏改一处。把回呼集中成一个明确对象并写进规格，等于在架构层设了一道**编译器管不到、但 code review 管得到**的边界。可落地的做法：任何被多个模块共用的 `ctx`／`deps` 对象，都在文档里列成表格并注明「少一个会怎样」——因为缺一个回呼的症状永远是「点了没反应」，而那是最难从代码推回原因的错误形态。
